## Problem Statement

Plan 5, phase 3, step 3 (the C headers), verbatim from `docs/love-port/plan-5.md`:

> 3. The C headers. Seen when
>    `grep -rnE -- '--.*(Copy of|\bC\b|memset|\b[a-z0-9_]+_t\b|\{0\})' game/`
>    finds only lines that are not about the C, each listed in the step note.
>    A comment that states a trap through the C is reworded to state the trap
>    without it, not deleted.

The C game was deleted in plan 4 and the phase-0 decisions say the Lua no
longer mirrors it: "Comparing with the C side by side is given up" and "The
`-- Copy of src/...` headers go". Yet a maintainer opening almost any file of
`game/` still reads the C first. At HEAD `14512d7` (step 3.1 done, step 3.2
not yet) the step's grep finds 385 comment lines in 91 of the 102 Lua files
of `game/`: 87 `-- Copy of src/...` headers, 210 lines naming a C type
(`button_t`, `vec_t`, `p8_graphics_t`, `uint32_t`), 111 naming "the C" ("as
the C does", "the C's wrap is unreachable"), 5 `memset` and 14 `{0}`
initializer notes. A wider vocabulary of the same kind sits outside that
grep: 59 more comment lines name a C file (`src/p8/gfx_software.c`,
`dump.c`, `replay.c`), a `NULL`, a `struct`, a pointer, `strlen`, `static`,
`unsigned`, the `-- Lua only` marker, a "ported / not ported" status, or a
`-- Generated by` header naming a generator that no longer exists. All told
100 of the 102 files carry at least one such line.

For the maintainer this costs on every read: the shape of a table is given
by a C type name nobody can look up without `git show 60e62c1`; a trap is
explained by a C behaviour that has no Lua equivalent ("C leaves argument
order unspecified", "the offer is on the stack: a callee that keeps a
pointer to it dangles"); status claims about the C are stale ("only
dump.c asserts it" — `dump.c` is gone; "Generated by make sin-table" — the
target is gone); and the `-- Lua only` marker contrasts each function with
a C original that the plan has stopped tracking. None of it is a trap or a
contract in the sense of `CLAUDE.md` § Comments, except the part each
comment wraps around the C: that part must survive in Lua terms.

All the step changes is comments, so every capture hash, end state and save
byte stays the same without any special effort, but each chunk still has to
prove it mechanically.

## Solution

Every comment of `game/` that describes the Lua through the C is either
deleted or reworded in Lua terms, by the bar of `CLAUDE.md` § Comments: a
comment stays only if it carries a trap someone would reintroduce (40 words
at most) or a contract the name does not state; it then states that trap or
contract in terms of the Lua code that exists now — its tables, fields,
functions and modules — never through a C type, file, construct or
behaviour. Everything else that only described the Lua through the C goes;
git keeps it.

No line of code changes: each changed file compiles to the same stripped
LuaJIT bytecode before and after, so `make e2e` keeps every `.json.sha256`,
`make end-state` every `.end-state`, and the save encoder every byte. The
one file that held nothing but a C header (`main_economy`, required by
nothing) is deleted once its two contract clauses have moved to the modules
that build those tables.

At the end the step's grep, and a wider C-vocabulary grep this PRD defines,
over all of `game/` find only lines that are not about the C, each listed in
the step note; `design.md` and `CLAUDE.md` § The game no longer describe
comment conventions or type names that this step removed; `warn-review`
gains a rule so the narration does not grow back.

## Implementation Decisions

- **The bar.** `CLAUDE.md` § Comments, applied to every comment line that
  names or relies on the C. A comment line is *about the C* when it names
  a C type (`*_t`), a C file or path (`src/...`, `*.c`, `*.h`), a C
  construct or library call (`memset`, `memcpy`, `memcmp`, `strlen`,
  `sizeof`, `{0}`, `NULL`, `struct`, `static`, a pointer, `char`,
  `unsigned`, `int`), "the C" in any form, a port status ("ported", "not
  ported", "Copy of", "Lua only", "Generated by" a deleted generator). Each
  such comment is classified:
  - **goes** when, the C part removed, nothing is left that is a trap or a
    contract the code does not state (copy headers, "declared in X.h,
    defined in Y.c", type-name restatements of a constructor, `{0}` notes,
    "as the C does" justifications, `-- Lua only` markers, status claims);
  - **reworded** when it carries a trap or a contract: the new text states
    it with the Lua names that exist now, in one sentence where possible,
    40 words at most for a trap; never longer than the comment it replaces.
- **Shape blocks.** The "Shapes, with the C field names:" blocks at the top
  of about 40 modules go as blocks. A field list survives only where no
  code in the module lists the fields (no constructor, zero function or
  literal building the table); it is then titled by the table's Lua role,
  not its C type ("An entity's header: { class, state, ... }"). Only the
  clauses that are contracts survive from the rest: what `nil` means for a
  field, `true`-or-`nil` fields, ownership and identity ("owned by the
  entity: set copies in, get copies out"), by-value tables never mutated,
  value ranges. Such a clause moves next to the constructor or function
  that makes it true when one exists, otherwise stays at the top of the
  module.
- **The entity header.** `engine.entity_class` keeps the header's and the
  class table's field lists and their contracts (no constructor lists
  them, and `CLAUDE.md` points there), reworded without `entity_t`,
  `entity_class_t` or "a pointer is the table, NULL is nil".
  `CLAUDE.md` § The game's "(the fields of `entity_t` in
  `game/engine/entity_class.lua`)" becomes "(the header fields listed at
  the top of `game/engine/entity_class.lua`)".
- **References to C files.** A C file whose Lua module exists is replaced
  by that module and function, when the reference carries a "keep in step"
  trap (the LÖVE backend's loops copied from `p8.gfx_software`; `love.pattern`,
  `love.sheet`, `love.slot`, `love.text`, `love.screen` as the LÖVE side of
  `p8.gfx_software`, `p8.vram`, `p8.palette`; `pad_nav`'s "keep in step
  with `pad_panel`'s box_at"; `draw_cost`'s midpoint loop of
  `p8.gfx_software`). A C file with no Lua counterpart (`dump.c`,
  `replay.c`, `asset_image.c`, `gpu_sizes.h`, `src/devtools/`, `src/cmd/`)
  is deleted from the comment; if the comment's claim depended on it, the
  claim is verified against the code as it is and either corrected (for
  example `gfx_software`'s "only dump.c asserts it": state what refuses a
  colour above 15 now, `love.backend`'s `check_color`, after reading it)
  or deleted.
- **Verify every status claim.** A claim that something is "not ported",
  "never called", "defined elsewhere", "only X asserts it" is checked with
  `git grep` against the base before it is reworded; a false claim is
  deleted, and the finding goes to the commit message.
- **Semantics the Lua emulates.** Where the Lua reproduces a C integer
  behaviour on purpose (`cint`'s truncation, `fixed`'s 16.16 raw value,
  32-bit wraps of hashes and stamps, `visual_random`'s unsigned state, the
  save's u32/i32 fields, `love.text`'s bytes above 127), the comment states
  the behaviour ("truncates toward zero", "a number in 0 .. 2^32 - 1",
  "wraps to 0 after 2^32 - 1, then skips to 1"), not the C type. `u32`/`i32`
  as names of save-format field widths are format vocabulary, not C, and
  may stay. "The C's wrap is unreachable" notes on Lua-number counters go.
- **Traps through C behaviour.** A trap explained by a C behaviour is
  reworded to its Lua reason when one exists: `probe`'s "Two statements: C
  leaves argument order unspecified" becomes the Lua reason (the two draws
  must happen in this order to keep the replays); `exit_queue`'s "as in the
  C: releasing it here would move the replays" keeps only "releasing it
  here would move the replays"; `economy_score_set_difficulty`'s note says
  the table is written in place, every field, so that a holder of the
  returned table sees the new values; `research`'s project table "zeroed in
  place" loses "as the C reuses the bytes". A trap whose reason exists only
  in C (`planet_trade`'s "the offer is on the stack: a callee that keeps a
  pointer to it dangles") is kept only if the Lua code still relies on the
  same rule (the callee must not keep the offer because the caller reuses
  it), verified by reading the callers; otherwise it goes and the commit
  message says why.
- **Zero constructors.** The `-- Lua only: x_t y = {0}, a new table`,
  `-- memset(...)` and "at its C zero" lines over `*_zero` functions and
  constructors go; a constructor whose contract is not in its name (it
  resets in place and keeps identity; it returns its argument; optional
  fields left `nil`) gets one sentence in Lua terms.
- **`-- Lua only` markers** all go, including the module headers of
  `save_storage` ("the storage backend ... over `love.filesystem`" keeps
  only what is not the C: a backend over `love.filesystem`) and the
  `gfx_software` slot-store export (keeps "for `love.slot`" if it is the
  only reader, verified).
- **Generated data modules.** The `-- Generated by make ...` first lines of
  `p8.quarter_wave`, `p8.sprite_sheet_packed`, `game.demo_data` and
  `game.bindings_default` name targets and C generators that are gone
  (`design.md` § Data tables and checks says so). `bindings_default`'s
  becomes "Edited by hand, in step with `bindings.default.cfg`: nothing
  checks the two agree." (the trap `bindings.default.cfg` states from the
  other side); `sprite_sheet_packed`'s becomes "Edited by hand, in step
  with `game/sprites.png`: nothing checks the two agree." (the trap
  `design.md` states); `quarter_wave`'s and `demo_data`'s go.
- **`game.main_economy`.** It holds only its C header and shapes and is
  required by nothing (`git grep 'game.main_economy'` empty at the base).
  Its two contracts move: "production, demand and happiness are nil until
  the first recompute" to `game.economy`, whose own header points to
  `main_economy` today; "each nil until the cheat sets it" for the
  placeholder's `research_points` and `credits` to the placeholder's
  constructor in `game.probe`. Then the file is deleted. It is the only
  file the step deletes; no other file is added, moved or renamed.
- **Strings stay.** Assert messages and `check_fields` type-name arguments
  that name the C (`"... extends entity_t"`, `"score_rows_entry_t"`,
  `"no route of src/ holds true: resource_t has no kind for it"`,
  `"one of draw_function_t"`) are code: they stay byte for byte, and the
  step note lists them as strings left for a later step (they are not
  comment lines and are not hits of the step's grep).
- **No asserts, no code.** No trap becomes an assert in this step, and no
  identifier, string, literal, statement or blank line between code lines
  changes; only comment lines and blank lines inside or around a deleted
  comment block. A comment whose correction would need a code change (a
  parameter rename such as `bindings`' `error`) is reworded around the code
  as it is.
- **The wider grep.** The plan's grep misses most file references and C
  vocabulary. This step's work covers both; the check used by every chunk
  and by the step note is the pair:
  - the step's grep:
    `grep -rnE -- '--.*(Copy of|\bC\b|memset|\b[a-z0-9_]+_t\b|\{0\})' game/`
  - the wider grep:
    `grep -rnE -- '--.*(src/|\b[a-z0-9_]+\.[ch]\b|NULL|\bstruct|pointer|Lua[ -]only|memcpy|memcmp|strlen|sizeof|\bstatic\b|unsigned|\bchar\b|\bint\b|Generated by|ported)' game/`
  Every hit left by either is listed in the step note with its reason
  (not about the C: a word that happens to match, a format field width, a
  string after `--` that is not a comment). Both are expected to leave few
  or no lines; an empty result is recorded as such.
- **`design.md`.** Only the sentences this step makes false change: in
  § Conventions inherited from the C, "A function the Lua adds is marked
  `-- Lua only` and, when another module needs it, exported ..." loses the
  marker clause; in "Data tables and checks", "their `-- Generated by`
  headers still name the deleted generators" is replaced by what the
  headers now say. The rest of the section is step 3.5's.
- **`warn-review`.** A rule is added after the last one (22 under
  H-3.2-5): "A comment that describes the Lua through the C — a C type,
  file, construct or behaviour, a port status, a `-- Lua only` marker —
  rather than stating a trap or a contract in Lua terms."
- **Step 3.2's comments.** Step 3.2 rewrites the comments whose 0-based
  contract it makes false (its PRD's § Comments). This step works from the
  comments as 3.2 leaves them: a line 3.2 rewrote is a hit like any other
  if it still names the C (H-3.2-2).
- **No guideline question was needed**: the phase-0 decision on the copy
  headers, the step's check, `CLAUDE.md` § Comments and the fact that only
  comments change settle every case above.

## Testing Decisions

- No test is added or changed. The step changes no behaviour, so the
  proof is mechanical, not a test: stripped bytecode identical per file,
  a diff of comment lines only, `lua-guard` (which blanks comments before
  checking, so a reworded comment cannot trip it), and the replays as the
  plan's net.
- A good check here is one that a code change cannot pass: the bytecode
  comparison is that check; `make e2e` and `make end-state` are run because
  the plan requires them, and are expected to be trivially green.
- `tests/lua/test_modules.lua` loads every module it finds; deleting
  `main_economy` removes one load and breaks nothing (no hard-coded
  count).
- Prior art: the `rework-comments` skill's gate (step 0's `luajit -b -s`
  comparison, line-range edits that refuse anything but comment), the
  per-chunk instruments and greps of steps 2.1 to 3.1.

## Out of Scope

- Renaming any identifier, exported or local, including `_t`-sounding
  locals, the `_module` suffixes and the `end_` field (step 3.4).
- `design.md` § Conventions inherited from the C beyond the two sentences
  this step makes false (step 3.5).
- 0-based comments and arrays (step 3.2), truth values (step 3.1).
- Strings that name the C (assert messages, `check_fields` type names):
  code, listed in the step note, not changed.
- Comments of `tests/` and `tools/`: the step's check is `game/` only.
